# Telegram Media Publisher

Локальное Windows-приложение для подготовки публикаций из папки с видео. Приложение работает только через исходящие запросы Bot API: `getMe`, `sendMessage`, `sendPhoto` и `sendMediaGroup`; polling, `getUpdates` и webhook не используются.

## Запуск MVP

```powershell
.\.venv\Scripts\python.exe -m pip install -r media_publisher_requirements.txt
.\.venv\Scripts\python.exe -m media_publisher.main
```

В окне выберите папку, укажите токен и Chat ID, затем нажмите «Сканировать». Настройки сохраняются в профиле Windows (`%APPDATA%/TelegramMediaPublisher/settings.json`), токен не попадает в репозиторий и не выводится в логи. Кнопки проверки подключения и тестовой отправки используют только введённые локально значения.

Для форум-группы выберите направление публикации и внесите его ID темы. Приложение отдельно запоминает ID для фильмов, мультфильмов, аниме, сериалов и остальных настроенных разделов. Пустой ID блокирует отправку теста, чтобы сообщение случайно не попало в основную тему. ID темы — средняя числовая часть ссылки вида `https://t.me/c/<chat>/<topic>/<message>`.

После сканирования выделите фильм или конкретный сезон. Приложение автоматически ищет карточку и данные выбранного сезона. Кнопка «Предпросмотр» показывает локально загруженный постер, рейтинги, голоса, жанры, актёров, общее и сезонное описание, дубляж и найденные серии. Все поля можно исправить, а постер — заменить локальным файлом.

Поиск объединяет Rezka, TMDB и OMDb: Rezka имеет приоритет для постера и карточки, TMDB добавляет сведения конкретного сезона, OMDb — IMDb и число голосов. Ключи TMDB/OMDb вводятся в окне и хранятся только в локальном `settings.json`. Нерелевантные и числовые запросы отбрасываются. Выбранный результат и внешний ID сохраняются в SQLite, поэтому повторно выбирать тот же сериал и сезон не нужно.

После подтверждения приложение обязательно отправляет `sendPhoto` с карточкой из `templates/movie.txt` или `templates/season.txt`, затем видео либо `sendMediaGroup` пакетами до 10 файлов с подписью из `templates/media_group.txt`. Состояние каждого шага хранится в SQLite: повторная попытка после сетевой ошибки продолжает с неотправленного пакета и не дублирует уже отправленный постер.

## Большие видео

Облачный Bot API по адресу `https://api.telegram.org` принимает видео и документы размером не более 50 МБ. До отправки постера приложение проверяет каждый выбранный файл и останавливает всю операцию, если лимит превышен — частичной публикации больше не будет.

Для исходных файлов до 2000 МБ используйте официальный локальный [Telegram Bot API server](https://github.com/tdlib/telegram-bot-api) в режиме `--local`, затем укажите его базовый адрес, например `http://127.0.0.1:8081`, в поле «Bot API URL». Для удалённого сервера используйте защищённый HTTPS или приватную сеть: токен бота входит в URL запроса. При переносе существующего бота на локальный сервер следуйте официальной процедуре `logOut` и направьте к одному серверу все процессы этого бота, включая основной polling-процесс.

Полный текст карточки больше не обрезается: первые 1024 символа отправляются подписью постера, оставшаяся часть — одним или несколькими сообщениями до 4096 символов, после чего загружается видео. Состояние продолжений также сохраняется, поэтому повтор после ошибки не дублирует уже отправленный постер.
